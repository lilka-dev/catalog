# Каталог Лілки

[English version / Англійська версія](README.md)

Вебсайт для перегляду й публікації застосунків, шпалер і модів для Лілки:
[catalog.lilka.dev](https://catalog.lilka.dev).

Усе в цьому репозиторії:

```
site/                  сайт (GitHub Pages)
api/                   lilka-catalog-api — Cloudflare Worker, у якому живе
                       каталог (база D1, файли R2), див. api/README.md
scripts/mirror_api.py  копіює каталог з API на Pages для пристроїв Лілка
.github/workflows/
  deploy-pages.yml     сайт і дзеркало: після push, щогодини й після схвалень
  process.yml          перевірка ClamAV та обробка нових завантажень
  api.yml              тести API на кожен PR; розгортання з main
```

## Як опублікувати застосунок, шпалери чи мод

1. Відкрийте [catalog.lilka.dev](https://catalog.lilka.dev) і натисніть
   **Увійти через GitHub**. Використовується лише публічний профіль.
2. Перейдіть в **Опублікувати**, заповніть назву й описи (українською та/або
   англійською), посилання на вихідний код і файли:
   - **застосунки й шпалери**: файл запуску (`.lua`, `.js`, прошивка `.bin` або
     архів), за потреби додаткові файли, мінімальна версія Keira;
   - **моди** (корпуси, деталі для друку): файли моделі замість файлу запуску;
   - іконка й до 6 знімків екрана.
3. Кожен файл перевіряє антивірус ClamAV, потім версію переглядає модератор.
4. Після схвалення вона одразу з'являється на сайті, а на Лілці — протягом
   години (дзеркало для пристроїв, описане нижче, оновлюється після схвалення
   і щогодини).

Ваші публікації, стан перевірки й коментарі модератора — у **Мої додатки**.
Новий реліз — **Мої додатки → Нова версія**.

Імена файлів: латиниця, цифри, `.`, `_` і `-`. До 8 МБ на файл і 24 МБ за одне
завантаження.

## Як це влаштовано

```
 catalog.lilka.dev (цей репозиторій, GitHub Pages)
   site/            сайт; читає <API>/catalog/... і API спільноти
   apps/ wallpapers/ mods/ authors.json
                    статичне дзеркало <API>/catalog для пристроїв Keira

 lilka-catalog-api (Cloudflare)
   Worker + D1 + R2  застосунки, версії, файли, користувачі, оцінки, модерація
   GitHub Actions    ClamAV, icon_min, стиснення зображень, package.zip
```

API віддає каталог під `/catalog` точно в тій структурі, яку `lilcatalog` у
Keira читає з `https://catalog.lilka.dev`:

```
{apps,wallpapers,mods}/index_<page>.json     по 12 ідентифікаторів на сторінку
<dir>/<id>/index.json                        повний маніфест
<dir>/<id>/index_short.json                  назва, короткий опис, файл запуску
<dir>/<id>/static/<file>                     файл запуску, додаткові файли, іконка, icon_min.bin, знімки
<dir>/<id>/package.zip                       manifest.yml + файл запуску й додаткові файли
authors.json
```

Прошивка, яка вже в людей, не може змінити адресу каталогу, тож workflow
публікації копіює це дерево на Pages (`scripts/mirror_api.py`) після кожного
push, кожного схвалення (`repository_dispatch: api-sync`) і щогодини. Копія
падає повністю, якщо бракує хоч одного файлу, тож пристрої ніколи не отримують
половину каталогу.

Публічний каталог сайт теж читає з цього дзеркала: його безкоштовно віддає
CDN GitHub, а кожен запит до API рахується в денний ліміт Worker. До API
звертаються лише вхід, публікація й модерація; адреса — у
`<meta name="lilka-api">` у `site/index.html`. Саме дзеркало коштує один запит
до API за запуск (`/catalog/export.json`), файли незмінених застосунків бере з
Pages, а щогодинний запуск зупиняється одразу, якщо нічого не змінилося.

## Локальна розробка

Запустіть API локально (див. [api/README.md](api/README.md)), скопіюйте його
каталог у `site/` і запустіть сайт:

```bash
pip install -r requirements.txt
MIRROR_SECRET=dev-mirror-secret python3 scripts/mirror_api.py --api http://localhost:8787 --out site
cd site && python3 -m http.server 8000
```

Відкрийте http://localhost:8000 і, щоб вхід і публікація йшли в локальний API,
виконайте в консолі браузера:

```js
localStorage.setItem('lilka-api-url', 'http://localhost:8787')
```

Скопійовані `site/apps/`, `site/wallpapers/`, `site/mods/` і `site/authors.json`
не комітяться.

## Модераторам

Модератори — це числові id користувачів GitHub у `MODERATORS` у `api/wrangler.toml`. Вони
бачать вкладку **Модерація**: версії, що чекають перевірки, з переглядом коду
й зображень, контрольними сумами й результатом антивірусу; схвалити,
відхилити з причиною, заблокувати автора; відкриті скарги.

Застосунки, перенесені зі старого репозиторію, належать обліковому запису
`lilka-catalog` і зберігають початкового автора. Модератор може передати
застосунок автору, коли той увійде на сайт: `PATCH /apps/<id>` з
`{"owner": "<login>"}`.
